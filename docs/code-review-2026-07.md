## 1. 수정한 버그

1. **마지막 강의 완료 시 화면 미갱신** — `goNextLesson()`(`app.js`)이 마지막 리그의 마지막 강의에서 완료 처리 후 `render()` 없이 `return`해, 진행률·완료 배지가 즉시 반영되지 않았다. `render()` 호출을 추가했다.
2. **인라인 코드 복사 리스너 중복** — `bindCodeCopy()`가 `.inline-code` 노드마다 `addEventListener`를 반복 호출했고, 발표 모드에서 슬라이드를 넘길 때마다(`renderPresSlide`) 메인 강의 영역의 기존 노드에 리스너가 계속 쌓여 클릭 1회에 복사·토스트가 여러 번 발생했다. `document.body`에 위임 클릭 리스너 1개(`bindCodeCopyDelegate`)로 교체했다.
3. **토스트 겹침** — `toast()`의 `setTimeout`을 취소하지 않아 연속 토스트 발생 시 이전 타이머가 새 토스트를 조기에 숨겼다. 타이머를 모듈 스코프에 저장하고 `clearTimeout` 후 재설정하도록 고쳤다.
4. **로컬 QR 인코더의 Reed-Solomon/버전 정보 버그** — `qr.js` 신규 작성 중 발견·수정(아래 2번 참고).

## 2. 개인정보/약속 위반 — 완료율 QR 외부 전송

`renderCompletionSubmit()`이 `https://api.qrserver.com`에 학생 이름과 진도 데이터가 담긴 완료율 코드를 URL로 전달해 QR 이미지를 받아왔다. 화면 안내 문구("서버로 전송되지 않습니다", `index.html`)와 실제 동작이 어긋났고, 학교망에서 외부 요청이 차단되면 QR 자체가 뜨지 않는 문제도 있었다.

`qr.js`를 새로 작성해 의존성 없는 QR 인코더(바이트 모드, 오류정정 레벨 M, 버전 1~40 자동 선택)를 브라우저 안에서 직접 그리도록 교체했다(`drawQr(canvas, text)`). 개발 중 다음 버그를 발견해 수정하고, jsQR + 자체 제작한 QR 라이브러리(`qrcode` npm 패키지)를 대조군으로 400회 이상의 랜덤 퍼즈 테스트와 버전 1~40 전수 테스트로 검증했다:

- Reed-Solomon 생성 다항식의 계수 순서가 인코더가 기대하는 순서와 반대로 되어 있어 오류정정 코드워드가 전부 틀리게 계산됨.
- 포맷 정보(format info) 두 번째 사본을 기록하는 좌표 배열이 dark module 위치(`size-8, 8`)까지 덮어써 고정 기준 모듈을 훼손함.
- 버전 7 이상에서 필요한 버전 정보 블록(6×3 BCH 부호)을 예약만 하고 실제로 기록하지 않음.
- 버전 13 이상 다수 행에서 손으로 옮겨 적은 블록 구조 표(오류정정 코드워드 수·블록 수·블록 길이)에 전사 오류가 있어, 검증된 값으로 표 전체를 교체.

## 3. 혼자 학습(코스웨어) 보완

기존에는 모범답안·자가 채점 장치가 전혀 없고(`content.js` 전수 확인 결과 44개 강의 모두 placeholder·chips만 제공), "생각해보기" 질문은 전부 동료 토론 전제라 혼자 학습자는 답도 상대도 없었다. 콘텐츠 자체는 수정하지 않고 코드로 다음을 보완했다:

- **AI 점검 프롬프트 복사** — 실습 카드 하단에 버튼 추가. 강의 목표·`completionRequirements`(수료 조건)·`checks` 항목·내가 작성한 실습값을 묶어 "이 기준에 맞춰 항목별로 평가해줘" 프롬프트를 만든다. 모든 강의에 `completionRequirements`가 있어 44개 강의 전부에서 동작한다.
- **AI와 토론하기 프롬프트 복사** — '생각해보기' 섹션에 버튼 추가. 원래 동료 토론용이던 질문을 "내 답을 먼저 묻고 반례로 토론 상대가 되어줘" 프롬프트로 바꿔 혼자서도 토론 형태의 학습이 가능하게 한다.
- **완료 처리 부드러운 안내** — '확인하기' 체크가 남아 있는 채로 완료를 누르면 한 번 확인창을 띄운다(강제 아님, 취소하면 진행하지 않음). 체크 항목이 없는 강의는 그대로 통과한다.

## 4. 접근성 개선

- 전역 `:focus-visible` 규칙 추가 — 기존에는 버튼/입력창 모두 `outline: none` + 15% 불투명 box-shadow 링만 있어 키보드 포커스가 잘 보이지 않았다. 뚜렷한 2px outline을 추가하되 마우스 클릭 시 동작은 그대로 유지했다.
- `prefers-reduced-motion: reduce` 대응 추가 — 전환·애니메이션이 16곳에 있었지만 동작 줄임 선호를 전혀 반영하지 않았다.
- 전체·리그 진행률 바에 `role="progressbar"`·`aria-valuenow` 추가, 렌더 시마다 갱신.
- 발표 모드 진입 시 포커스를 닫기 버튼으로 이동하고 종료 시 이전 포커스로 복귀. 온보딩 오버레이 표시 시 '시작하기' 버튼으로 포커스 이동.

## 5. 제거한 죽은 코드

`practice.kind === "mini"` 분기와 `updatePreview()`의 비-build 미리보기 분기(앱 이름·화면 문구·색상 필드를 하드코딩)를 제거했다. `content.js` 44개 강의 전수 확인 결과 `mini` kind를 쓰는 강의는 0개였다.

## 6. 콘텐츠 저작 권장 (이번 라운드 미수정)

코드가 아닌 `content.js` 데이터 저작이 필요해 이번 리뷰 범위에서 제외했다. 별도 작업으로 진행 권장:

- 강의 단위 교사 지도안(`facilitator`)은 44개 중 1개(`setup-rookie`), 발표자 노트(`presenterNotes`)는 2개뿐이고 서로 다른 하위 키 스키마를 쓴다. 통일된 스키마로 전 강의 확장 필요.
- `checks`가 `completionRequirements`를 그대로 중복하는 강의가 있다(예: `build-rookie`, `share` 계열). 중복 정리 검토.
- 다크 모드 미지원(하드코딩 라이트 토큰만 존재). 어두운 발표 환경·OS 다크모드 사용자를 위해 검토 필요.
- `id: "share"`가 세 리그에서 재사용됨(리그별 상태 분리 구조상 현재는 버그 아님). 향후 전역 id 조회 로직을 도입할 경우 반드시 리그 스코프를 함께 고려해야 한다.

## 검증 방법

Node의 `qrcode`(참조 인코더)·`jsqr`(디코더) 패키지를 스크래치 디렉터리에 설치해 `qr.js`를 버전 1~40 전수 검증(포맷 정보 BCH 계산 대조), 랜덤 문자열 400회 퍼즈 테스트(한글 포함), 경계값(빈 문자열/최대 용량 2331바이트/초과 시 예외) 테스트를 통과시켰다. Playwright(사전 설치된 Chromium)로 실제 브라우저에서: 44개 강의 전체 순회 시 콘솔 에러 0건, 실습값 저장 후 새로고침 유지, 마지막 강의 완료 시 진행률 즉시 갱신, 확인하기 미완료 시 확인창, 인라인 코드 복사 단일 실행, 발표 모드 포커스 이동/복귀, 완료율 코드 생성→QR 캔버스 렌더→jsQR로 실제 디코드→`decodeCompletionCode()`로 파싱→`?mode=collect` 화면에 반영까지 전 과정을 확인했다.
