- 루키는 "코드를 칸에 붙여넣으면 실행", 프로는 "Git 설치 → 에이전트 설치 → 프로젝트 폴더 → 로컬 실행"으로 한 번에 뛴다.

### 2-3. Git 실습이 개념뿐

`git add / commit / push / init` 전부 **0회 언급**. `github` 강의는 "커밋합니다", "Push합니다" 수준이고 실습은 저장소 이름을 텍스트로 적는 것이 전부였다.

**조치** — 처음 한 번의 연결 절차와 이후 반복할 세 명령을 백틱으로 넣었다(`renderText`가 클릭 복사 가능한 `<code>`로 렌더). 터미널 여는 법, `.gitignore` 실제 내용, 그리고 **명령줄을 쓰지 않는 대안**(에이전트 위임 / GitHub Desktop / github.dev 소스 제어)을 병기해 설치 불가 경로 사용자도 완주할 수 있게 했다.

### 2-4. 도구 설명의 사실 오류

Codex를 4곳에서 "Windows GUI 프로그램"이라 단정하면서 링크는 `github.com/openai/codex`, Claude Code도 "Windows GUI 프로그램"인데 링크는 `claude.ai/code`였다. 초보자가 그 링크에서 GUI 설치 파일을 찾으면 없다 — 실습 실패로 직결된다.

**조치** — 실제 제공 형태로 정정했다. Claude Code는 터미널 CLI 기본 + IDE 확장·데스크톱 앱·웹, Codex는 CLI·IDE 확장·웹, Antigravity는 에디터형 앱. 셋 중 **하나만** 고르면 된다는 점도 명시했다.

### 2-5. 디버깅이 가장 늦게, 가장 얇게 배치

루키 졸업 요건에 "오류를 1개 이상 직접 수정했다"가 있는데 **고치는 방법을 가르치는 강의가 없었다.** F12·콘솔은 마스터 `deploy-check`/`logs`에 각 1회만 등장했다 — 바이브코딩에서 시간을 가장 많이 잡아먹는 스킬이 맨 끝에 있었다.

**조치** — `build-rookie`(20→30분)에 오류 고치기 4단계를 넣었다. ① 기대와 실제의 차이를 한 문장 ② F12 → Console 빨간 글자 복사 ③ "이 증상, 이 에러, 최소한만 고쳐 줘" 재요청 ④ 다시 붙여넣어 확인. `terms`에 개발자 도구·콘솔 추가.

### 2-6. 프로 → 마스터 약속 미이행

`api-security-pro`가 "실제 네이버 호출은 서버 프록시가 필요하므로 마스터로 넘긴다"고 명시했으나, 마스터 `travel-api-gemini`도 "서버 프록시가 필요하다"는 설계 문장에서 끝났다. **네이버 쇼핑 API는 전 코스에서 한 번도 실제 호출되지 않았다.** `db-auth-integration`도 Supabase/Firebase/Clerk 이름 소개와 후보 선택 드롭다운이 실습의 전부였고, RLS는 `app.js`의 도구 매뉴얼에만 있고 강의 본문에 없었다.

**조치** — 마스터를 실구현으로 재작성했다.

- **`env`(15→20분)**: 공개 키와 비밀 키의 구분을 추가. 기존에는 "모든 키는 숨긴다"만 가르쳐, Supabase anon key가 브라우저 노출이 정상 설계라는 사실을 몰라 다음 실습에서 막히거나 반대로 `service_role` 키를 안전하다고 오해하게 되어 있었다. `.env.local` 생성 → `.gitignore` 추가 → `git status` 확인 절차 추가.
- **`travel-api-gemini`(25→40분)**: 서버 프록시를 실제로 만든다. `api/` 폴더 → 에이전트에 중계 파일 요청(지시문에 "키는 `process.env`에서만 읽고 응답에 포함하지 마" 명시) → 환경변수 등록 → 호출 대상을 `/api/…`로 교체 → 재배포 → 페이지 소스 보기와 F12 Network 탭에서 키 노출 0건 확인.
- **`db-auth-integration`(25→45분)**: Supabase를 기본 경로로 고정. 프로젝트 생성 → `trips` 테이블 + `owner_id` → Email 로그인 → **RLS 정책 `owner_id = auth.uid()`** → 에이전트로 연결 → **계정 A로 저장 후 시크릿 창 계정 B에서 안 보이는지 실제 검증**. RLS가 왜 화면 필터보다 안전한지(브라우저 코드는 누구나 고칠 수 있다)를 anon key 공개 가능성과 연결해 설명했다.

## 3. 검증 문구 재작성 (`checks` 38강)

44강 중 **42강이 `checks`와 `completionRequirements`가 완전히 같은 문자열**이었다. 부분 중복이 아니라 전면 복사라, 학습자가 누르는 "확인하기"가 수료 조건을 한 번 더 읽는 것에 그쳤다.

역할을 갈랐다. `completionRequirements`는 수료 조건 요약으로 두고, `checks`는 관찰 가능한 결과로 전면 교체했다.

| 이전 | 이후 |
|---|---|
| "Repository를 만들었다" | "GitHub 저장소 페이지에 내 파일 목록이 보인다" |
| "로그인 서비스 후보를 정했다" | "다른 계정으로 로그인하면 앞 계정의 데이터가 보이지 않는다" |
| "환경변수 이름을 적었다" | "페이지 소스와 Network 탭 어디에도 키 문자열이 없다" |
| "배포 URL이 열린다" | "시크릿 창에서 열어도 앱이 뜬다" |

문서 작성 강의는 실행할 것이 없으므로 자기 결과물을 스스로 판정할 수 있는 형태로 바꿨다(예: "PRD만 읽고도 남이 같은 앱을 만들 수 있을 만큼 구체적이다").

**부수 효과**: `buildSelfCheckPrompt`(`app.js:703`)가 `completionRequirements` + `checks`를 합쳐 AI 채점 프롬프트를 만든다. 지금까지는 같은 문장이 두 번 들어갔지만 이제 서로 다른 기준이 들어가므로, 엔진을 고치지 않고도 혼자 학습자의 AI 자가채점 품질이 올라간다.

## 5. 반응형 가로 넘침 (CSS)

44강을 375px에서 전수 측정하니 10개 강의에 가로 스크롤이 있었다. 4개는 이번 작업 전부터 있던 것이고, 나머지는 새로 추가한 긴 명령·칩·확인 문구가 기존 CSS의 약점을 드러낸 것이다. 원인은 전부 "줄바꿈 불가 요소가 컨테이너를 밀어냄"이었다.

| 지점 | 원인 | 조치 |
|---|---|---|
| `code.inline-code` | `inline-flex` + `white-space:nowrap` | `max-width:100%`, `white-space:normal`, `overflow-wrap:anywhere` |
| `.guide-chip` | `inline-flex`로 긴 칩이 안 접힘 | 위와 동일 + `text-align:left` |
| `.choice` | button 기본 `nowrap` 상속 | `white-space:normal`, `min-width:0` |
| `input/textarea/select` | 폼 컨트롤 기본 고유 폭이 그리드 트랙 확장 | `min-width:0`, `max-width:100%` |
| `.result` | `pre-wrap`이지만 URL 같은 긴 토큰은 안 끊김 | `overflow-wrap:anywhere` |
| `.check-item span` | `word-break:keep-all`에서 `SECRET·API_KEY` 연쇄가 안 끊김 | `min-width:0`, `overflow-wrap:anywhere` |

이어서 태블릿·소형 노트북 구간과 폰트 차단 상황까지 함께 정리했다.

| 지점 | 원인 | 조치 |
|---|---|---|
| `.topbar` | 헤더 한 줄에 약 1100px이 필요한데 줄바꿈 breakpoint가 760px이라 **761~1279px 전 구간**이 깨졌다 | `@media (max-width: 1279px)`에서 줄바꿈 허용, 진행률·개발자 정보를 다음 줄로 |
| `body` | `overflow-wrap: break-word`는 줄바꿈만 허용하고 **최소 폭 계산은 줄이지 않는다** — "Claude Code·Antigravity·Codex" 같은 토큰이 컨테이너를 밀어냄 | `overflow-wrap: anywhere` (`word-break: keep-all`이 함께 걸려 한글 단어는 유지됨) |
| `.visual` | 도식 단계 상자의 최소 폭이 바깥 폭을 결정 | `contain: inline-size` + `overflow-x: auto` — 도식 안에서만 넘김 |

| `#submitCodeText` | 완료율 base64 코드가 한 줄이라 **3034px**로 페이지를 밀어냄(기존 결함) | `white-space: pre-wrap` + `overflow-wrap: anywhere` |

결과: **320~1920px 14개 폭 × 44강 전부 가로 넘침 0**. 폰트 CDN 차단 상태와 모든 접기 섹션을 펼친 최악 조건에서도 동일하다. 작업 전부터 있던 결함(375px 4개, 768~1279px 44개, 접기 펼침 시 1811px)도 함께 해결됐다.

## 6. 폰트 CDN 의존 해소

`styles.css`가 `cdn.jsdelivr.net`에서 Pretendard를 `@import`했다. 문제는 두 가지였다.

1. 폴백 스택이 `-apple-system, 'Apple SD Gothic Neo', sans-serif`뿐이라 **Windows용 한글 폰트가 없었다.** 교무실 PC에서 CDN이 막히면 한글이 일반 sans-serif로 떨어진다.
2. `@import`는 `styles.css`를 받아 파싱한 뒤에야 요청이 시작돼 표시가 늦다.

자체 호스팅은 검토했으나 채택하지 않았다. dynamic-subset 배포는 woff2 파일이 수백 개라 빌드 단계가 없는 이 저장소에 넣기 부적절하고, 통합본은 1MB를 넘어 학교망에서 오히려 불리하다.

대신 **폰트를 못 받아도 제대로 보이게** 고쳤다.

- `--font-sans` 토큰 신설 — `Pretendard → -apple-system → system-ui → Apple SD Gothic Neo → Malgun Gothic/맑은 고딕 → Noto Sans KR`. Windows·macOS·Android·ChromeOS가 모두 자기 한글 폰트로 대체된다.
- `--font-mono` 토큰 신설 (`D2Coding` 추가).
- `@import`를 `index.html`의 `<link>` + `preconnect`로 옮겨 병렬로 받게 했다. CDN이 막히면 이 요청만 실패하고 나머지는 정상 동작한다.
- 내려받는 포트폴리오 HTML(`app.js`의 `buildPortfolioHtml`)은 애초에 웹폰트를 불러오지 않아 **항상** 폴백을 쓴다. 여기에도 같은 한글 스택을 넣었다.

CDN을 실제로 차단한 상태로 44강을 렌더해 폴백이 적용되고 레이아웃이 깨지지 않는 것을 확인했다.

## 7. 유지한 강점

- **`build-rookie`의 실행 미리보기 + 자동 점검 루브릭** — 초보자가 설치 없이 즉시 피드백을 받는 구조로, 이 코스의 가장 큰 자산이다.
- **44강 동일 골격** (목표 → 한 줄 핵심 → 읽고 이해하기 → 용어 → 도식 → 생각해보기 → 따라하기 → 실습 → 확인하기) — 인지 부하가 낮다.
- **보안 서사의 연속성** — 루키(가드레일) → 프로(공개 API vs Secret API) → 마스터(환경변수·RLS·권한)로 끊기지 않는다. 이번에 anon/service 키 구분과 서버 프록시가 추가되어 사슬이 완결됐다.
- **혼자 학습 보완 기능** — `buildSelfCheckPrompt` / `buildDiscussionPrompt` / 도움 요청문 생성이 코드 레벨에서 이미 동작한다.
- **톤 가이드 준수** — 학생·성인 교사 공용 문체가 44강에 일관되게 지켜지고 있다.

## 8. 남긴 문제

- **`cicd` 강의는 개념 수준 유지** — 이 단계에서 GitHub Actions 실습까지 요구하면 완주율이 떨어진다고 판단해 의도적으로 남겼다.
- **`id: "share"`가 세 리그에서 재사용됨** — 리그별로 상태가 분리돼 현재는 버그가 아니다. 향후 전역 id 조회 로직을 도입하면 반드시 리그 스코프를 함께 고려해야 한다. (2026-07 리뷰에서도 지적)

## 9. 검증 방법

`content.js` 정합성 검사와 브라우저 실동작 검사를 스크래치에 두고 각 커밋 전에 돌렸다.

**정합성 (8항목, 전체 통과)**
1. `node --check` + `COURSE` 파싱 — 리그 3 / 페이지 44 / `PROJECT_TRACKS` 5
2. **id 불변** — 44개 id를 기준 커밋과 순서까지 대조. 페이지 id는 `state.levels[league].pages[id]`의 키라 바뀌면 학습 기록이 유실된다
3. **runPlan 정합성** — 세션 제목의 `(NN분)`이 `estimatedMinutes` 합계와 일치하는가, 참조 id가 실재하는가, 모든 강의가 최소 하나의 세션에 등장하는가
4. `checks === completionRequirements`인 강의 0개
5. 스키마 불변 — `app.js`가 읽지 않는 새 필드 없음
6. `summary` 백틱 없음 (`textContent`라 그대로 노출된다)
7. 잔여 grep — 순번 참조 0, "Windows GUI" 0, RLS·anon key·`api/` 언급 존재

**브라우저 (Playwright + 사전 설치 Chromium)**
- 44강 전체 순회, 제목 렌더 확인
- `build-rookie`: HTML 붙여넣기 → iframe `srcdoc` 반영 → 자동 점검 패널 표시 → 비밀값 의심 문자열 경고 동작
- **기존 학습 기록 호환** — 작업 전 버전에서 저장한 `localStorage` state를 주입하고 새 버전을 로드해 3개 리그의 실습 입력이 모두 복원되는지 확인(id 불변의 실증)
- 교사 모드에서 새 시간표(5차시 표준형 / 90분 특강형) 노출
- 발표 모드 진입 및 슬라이드 세로 넘침 없음
- **가로 넘침 전수 측정** — 320·360·375·414·600·760·761·768·820·900·1024·1180·1279·1280·1440·1920px × 44강을, 폰트 CDN 정상/차단 × 접기 기본/모두 펼침 네 조합으로 검사. 전부 0

이 환경의 콘솔 에러 1건은 샌드박스 프록시가 외부 폰트 CDN을 차단해 발생한 것으로, 작업 전후가 동일하며 실제 네트워크에서는 발생하지 않는다.
